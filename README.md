# 千鸟酱与菲姆酱

两套可以在QQ群里聊天、玩游戏和提供群工具的机器人。

**第一次接触机器人，建议先配置一台，确认能收到消息后再开启第二台。** 本文按Windows64位、Python3.12、协议端与Python程序在同一台电脑的情况编写。

> 本仓库是源码发行版，不包含作者的QQ登录信息、密钥、聊天记录、数据库和素材图库。部分老插件需要补充资源，尚未在空白电脑上完整验证全部功能一键部署；遇到缺失依赖或素材时，请看最后的排查表。

## 能做什么

| 类别 | 功能举例 |
| --- | --- |
| 群内游戏 | 技能决斗、快速决斗、赛马、娶群友、今日小猪 |
| 日常互动 | 签到、好感、藏品、求签、人物互动 |
| 聊天 | 本地问答词库、群聊学习、可选DeepSeek云聊、固定人格 |
| 群工具 | 图片帮助、群语录、漂流瓶、公告、临时禁言机器人 |
| 统计 | 日、周、月、年词云与发言排行 |
| 减少刷屏 | 群忙自动判断、定时合并结果、滚动触发限流 |
| 词库查看 | 一次最多20张图片，放在同一条合并转发记录里 |

具体启用功能以各自的`bot.py`和群内“帮助”为准，两台的历史插件不完全相同。

## 第一步：认识需要运行的两个程序

- **QQ协议端**：登录你自己的QQ、收发消息，例如你已有的NapCat。需要单独准备，本仓库不附带其程序或登录文件。
- **本项目的Python程序**：处理“签到”“发起决斗”等指令，把结果交给协议端发送。

消息流向：**群友 → QQ协议端 → 本项目 → QQ协议端 → 群聊**。

`OneBot v11`是两边约定的通信方式；“反向WebSocket”是协议端主动连接本项目。后面按表填写地址和口令即可。两台机器人要分别使用自己的QQ账号、配置和端口。

## 第二步：下载代码

在[仓库首页](https://github.com/CWCC-EDU/qqbot-duo)点击绿色 **Code → Download ZIP**，下载后完整解压到容易找到的位置，例如`D:\qqbot-duo`。

打开解压后的文件夹，确认能看到`run.py`和`requirements.txt`：

```text
qqbot-duo/
├─ run.py                 启动入口
├─ requirements.txt       Python依赖清单
├─ testbot/               千鸟酱
├─ testbot_2/             菲姆酱（Seraphim）
├─ shared/                两台共享的代码
├─ docs/                  详细说明
└─ third_party/           上游来源和许可证
```

请保留完整结构，不要只复制`testbot`文件夹。

## 第三步：安装Python和依赖

安装 **Python3.12的Windows64位版本**，可在[Python官方Windows下载页](https://www.python.org/downloads/windows/)查找3.12。本项目启动入口限定3.12，其他大版本不能直接替代。

在`run.py`所在文件夹空白处右键，选择“在终端中打开”，默认PowerShell即可。逐行执行，看到上一行结束后再运行下一行：

```powershell
py -3.12 --version
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
```

第一行应显示`Python 3.12.x`。`.venv`是本项目专用的Python环境；以后直接使用上述路径启动，**不需要激活Conda，也不需要执行Activate.ps1**。最后一行安装部分图片功能使用的浏览器。

依赖安装报错时，保留pip最后一段错误。清单来自已有环境，部分历史库可能需要兼容处理，没有验证空白电脑完整安装成功。不要通过上传旧环境、登录缓存或数据库解决安装问题。

## 第四步：生成配置并填写自己的信息

在同一终端执行：

```powershell
.\.venv\Scripts\python.exe run.py testbot --prepare
.\.venv\Scripts\python.exe run.py testbot_2 --prepare
```

这一步只生成缺失配置，不启动机器人，也不覆盖已有配置。用记事本分别打开：

- `testbot/.env`：千鸟酱配置。
- `testbot_2/.env`：菲姆酱配置。

如果找不到文件，确认命令成功，并在资源管理器中显示文件扩展名。保存时不要变成`.env.txt`。

| 项目 | 怎么填 |
| --- | --- |
| `SUPERUSERS` | 你自己的QQ号，表示谁是超管。例如`SUPERUSERS=["你的QQ号"]`，把“你的QQ号”换成数字，保留引号和方括号。 |
| `ONEBOT_ACCESS_TOKEN` | 自己生成的随机口令，协议端和Python两边必须一致。 |
| `PORT` | 千鸟默认8080，菲姆默认8081，两台不能用同一个端口。 |
| `NICKNAME` | 机器人的名字，模板已经分别填好。 |
| `DEEPSEEK_API_KEY` | 可以先留空，不使用云聊时不需要注册或购买模型服务。 |

生成OneBot随机口令可执行：

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
```

将输出复制到本机`.env`的`ONEBOT_ACCESS_TOKEN=`后，并填到对应协议端的OneBot连接配置中。它**不是WebUI管理口令，也不是DeepSeek密钥**。两台可使用不同口令。

其他项先保留模板。`HOST=127.0.0.1`表示只接受本机连接。如果协议端和Python在两台不同电脑上，需要另行配置网络，不能直接照抄本文的本机地址。

## 第五步：准备图片和其他资源

求签图、部分模板和字体未随源码发布，详见[资源清单](docs/ASSETS.md)。

- 千鸟求签图：放在`testbot/testbot/plugins/testforsera/fortune_cards/`，文件名对应同目录的`cards.json`。完整素材为8个角色、每个8张。
- 菲姆原版求签图：放在`testbot_2/data/gacha/`，至少准备一张自己有权使用的图片。
- 其他插件提示缺少字体、模板或数据定义时，按该插件日志和资源说明补充。

千鸟启动入口会检查是否存在求签PNG；只放一张不代表全部签都能使用，请按清单补齐。两台都可能因历史资源缺失导致部分插件加载失败。

停用某项功能可编辑对应`bot.py`，在其`nonebot.load_plugin(...)`行首加`#`。但千鸟入口的求签检查独立于插件加载，注释加载行并不能绕过素材检查；初学者建议先补齐素材，不要批量删除代码。

## 第六步：连接QQ协议端

已有可用NapCat的用户继续使用自己的安装。新安装请查阅[NapCat官方入口](https://napcat.napneko.icu/)当前说明。本项目不提供安装包、登录文件或作者的QQ账号。

在协议端找到 **OneBot v11 → WebSocket客户端／反向WebSocket** 设置，分别填写：

| 机器人 | Python端口 | 反向WebSocket地址 |
| --- | --- | --- |
| 千鸟酱 | 8080 | `ws://127.0.0.1:8080/onebot/v11/ws` |
| 菲姆酱（Seraphim） | 8081 | `ws://127.0.0.1:8081/onebot/v11/ws` |

将对应`.env`的`ONEBOT_ACCESS_TOKEN`填到该连接的token设置，启用并保存。不同版本按钮名称可能不同，认准协议和连接方向；不要把这个地址填成HTTP上报地址，也不要把8080/8081当成WebUI管理端口。

使用你自己的QQ账号完成登录。只运行一台，只配置对应的一行；两台分别连接自己的端口。

## 第七步：启动并验证

在仓库根目录的终端启动千鸟：

```powershell
.\.venv\Scripts\python.exe run.py testbot
```

再开一个终端启动菲姆：

```powershell
.\.venv\Scripts\python.exe run.py testbot_2
```

两个窗口保持打开。看到Python开始监听，并出现机器人连接信息后，在已加入的测试群发送`帮助`或`今日词云`。没有历史消息时提示暂无统计，属于正常情况。

出现`Failed to import`说明对应插件没加载成功，需要处理其缺失资源或依赖。**服务器开始监听不代表所有插件都成功加载。**

停止时在对应终端按`Ctrl+C`，等待退出再关窗口。以后启动无需重复安装依赖，也不用每次执行`--prepare`。

## 可以先试的指令

| 指令 | 作用 |
| --- | --- |
| `帮助` | 显示帮助，管理员能看到相应管理入口。 |
| `签到` / `今日小猪` | 日常互动与小猪玩法。 |
| `发起决斗 @群友` / `快速决斗 @群友` | 两种决斗玩法。 |
| `今日词云` / `本周词云` / `本月词云` / `年度词云` | 统计从机器人开始运行后积累。 |
| `今日发言排行` | 本群发言排名。 |
| `查询词库` | 按原权限查询，一次最多20张图片放进一条合并记录。 |
| `查询词库 从第21张` | 继续查看，优先用结果中给出的续查指令。 |
| `查询词库 第1页 文字` | 改用独立的文字分页。 |

大部分指令不加前缀。决斗选招和两台同群时的区分，按各自决斗设置执行。

群忙功能默认关闭，群管和超管可设置：

```text
群忙合并 自动
设置群忙阈值 60 20 4
设置群忙汇总 60 10
设置群忙限流 60 3
群忙状态
```

依次表示：自动判断；最近60秒达到20条、4人即进入群忙；每60秒或10次操作汇总；群忙时60秒最多3次新触发。已有对局后续操作放行。详细设置见[群忙说明](docs/GROUP_BUSY.md)和[词库图片说明](docs/WORD_BANK.md)。

## DeepSeek是可选项

建议先跑通QQ连接和本地功能，再配置本机`DEEPSEEK_API_KEY`或`runtime/deepseek.key`，按机器人内的云聊帮助设置开关和预算。不要把密钥写进源码或提交GitHub。

公开版不会继承作者原来的群号、群友画像或聊天记忆。模型调用产生你自己账号的费用，配置好预算后再开启主动接话。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| `py`不是命令 | Python3.12及启动器是否安装；安装后重新打开终端。 |
| 找不到`run.py`／`requirements.txt` | 终端是否在仓库根目录，而不是`testbot`内部。 |
| `ModuleNotFoundError` | 安装是否成功，启动是否使用`.venv\Scripts\python.exe`。 |
| pip找不到版本／依赖冲突 | 保留最后的错误；历史依赖组合可能需要兼容处理，尚未验证干净安装。 |
| 缺少图片、字体、模板 | 按[资源清单](docs/ASSETS.md)补齐，旧运行数据库不能替代素材。 |
| 端口占用 | 是否重复启动，或两台都用了8080；改端口后协议端地址也要改。 |
| 连接被拒绝 | Python是否监听、地址端口和路径是否对应、两边是否在同一台电脑。 |
| 401／403／鉴权失败 | OneBot token是否一致，不要混用WebUI密码。 |
| QQ在线但不回复 | Python是否连接；插件是否加载；权限、群开关、禁言和限流是否允许。 |
| 部分功能能用、部分不能 | 看对应插件报错和资源要求，不只看启动最后一行。 |
| 词库图迟迟没收到 | 等待本次超时提示，确认后用文字模式，不要连续重复查询。 |
| 关窗口后不回复 | Python和协议端都需要持续运行，关闭窗口会停止服务。 |

反馈问题请附上系统、Python版本、复现步骤和**去掉密钥及账号后的最后一段报错**。不要公开`.env`、带token的管理链接、数据库和QQ登录文件。

## 备份和更新

每台的`data/`、`database/`和`.env`是自己的运行资料。备份前先停对应机器人，分别保存在私有位置。`runtime/`可能包含密钥、用量账本和共享缓存，按需私下备份。

更新源码前先备份。不要把别人的数据库覆盖到自己的实例，也不要把NapCat或QQ客户端登录目录上传到本仓库。
